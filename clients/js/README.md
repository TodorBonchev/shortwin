# @shortwin/client

The short.win program client for [`@solana/kit`](https://github.com/anza-xyz/kit) 8.3.0, generated by
[Codama](https://github.com/codama-idl/codama) from the program's Anchor IDL (ARCHITECTURE §1.1, §1.2).
It has typed builders and parsers for every instruction, decoders for every account and event,
PDA helpers, the error codes, and the program plugin.

Everything under `src/generated/` is generated; do not edit it. `src/helpers.ts` is
hand-written: `ShareEpoch` records (`findShareEpochPda`, `getShareEpochCodec`,
`getShareEpochAccountMetas` for the lender instructions' remaining accounts), which no M1
instruction names, and `PodU128` / `PodI128` ↔ `bigint`. `idl/shortwin.json` is a
verbatim copy of `target/idl/shortwin.json` from `anchor build`. Both are committed, and CI
rebuilds and diffs them (the `codama` job in `.github/workflows/ci.yml`).

Until 1.0.0 `idl/` also held `complete_curve.json`, the IDL of the stateless straddle helper
(`programs/complete_curve`, M5). The helper was retired with pump's v3 exits before it was ever
deployed (design pump-final §10–§11, owner decision D2), and its IDL left with it; the audited
1.0.0 copy stays in git history (`git show v1.0.0:clients/js/idl/complete_curve.json`).

## Regenerate after a program change

```sh
anchor build --tools-version v1.57 --arch v3          # writes target/idl/shortwin.json
pnpm install
pnpm --filter @shortwin/client idl:sync               # target/idl/shortwin.json -> idl/
pnpm --filter @shortwin/client generate               # idl/shortwin.json -> src/generated/
pnpm --filter @shortwin/client check                  # typecheck + tests
```

`idl:sync` takes a path argument or `$SHORTWIN_IDL` when the build is not in `target/` (for
example with `CARGO_TARGET_DIR` set).

## Pins and generator options

Pinned devDependencies (ARCH §1.1): `codama` 1.11.0, `@codama/nodes-from-anchor` 1.5.6,
`@codama/renderers-js` 2.5.0, plus `typescript` 5.9.3 and `@types/node` 24.19.0. The only
runtime dependency is `@solana/kit` 8.3.0. The lockfile is the workspace's `pnpm-lock.yaml`.

`codama.json` (repository root) holds the renderer options and one `before` visitor. Its
package folder argument `.` is relative to this package, because `pnpm run generate` runs the
Codama CLI from here:

- `before`: `updateInstructionsVisitor` makes `sync_lender`'s `owner` an **either** signer
  (`isSigner: "either"`). The program reads it as a plain account and converts the position
  through a rebase record only with its signature (KI65-REV-SEC1); unsigned, the sync stops at
  a rebase record with the pot-only touch (KI-66: the surplus up to the record moves to the pot,
  nothing converts), so the IDL marks it `signer: false`. With the visitor a caller passes the
  owner's `Address` for a third party's sync (plain catch-up, the pot-only touch), or its
  `TransactionSigner` to sign (role `READONLY_SIGNER`). `RebaseNeedsOwner` (6107) stays in the
  error table as the program's post-condition; since KI-66 no path returns it.

- `kitImportStrategy: "rootOnly"` — the generated code imports only `@solana/kit` and its
  `@solana/kit/program-client-core` subpath.
- `importExtension: "ts"`, `erasableSyntax: true` — relative imports carry `.ts`, and there are
  no TypeScript enums. The sources run under Node's type stripping (Node ≥ 22.18; the repo pins
  24.21.0), bundlers (Vite) consume them directly, and `tsc` checks them with
  `allowImportingTsExtensions`.
- `syncPackageJson: false` — the renderer leaves this `package.json` (and its pins) alone.

## Tests (`test/`, `node --test`)

- `layout.test.ts` is the **T-LAYOUT Codama leg** (ARCH §2.3, §8.2). It parses every
  `layout!(…)` block and `SPACE` assert of `programs/shortwin/src/state/layout_asserts.rs`.
  For every field of every zero-copy type, it checks that the generated encoder puts the field
  at the asserted offset: it encodes the zero value, changes only that field, and asserts that
  the first changed byte is the offset. It also checks every asserted size. A field added to
  that file is covered without editing the test. `ShareEpoch` is not in the IDL yet (no
  instruction names it as a typed account), so the test lists it as an expected absence;
  `ShortPosition` and `WalletExposure` are in it since M2's `open_short`.
- `helpers.test.ts` checks the hand-written `src/helpers.ts` (the `ShareEpoch` codec, PDA
  and remaining-account metas the IDL cannot describe before M2, and the `PodU128` / `PodI128`
  ↔ `bigint` conversions) against the Rust structs, and the Borsh `LenderPosition` decoder's
  field order against `state/lender.rs`.
- `client.test.ts` checks the program id against `declare_id!`, and that every `#[program]`
  instruction has builders and parsers and its Anchor discriminator. It checks the error codes
  against the declaration order in `errors.rs` (from 6000), and `crank_sol_usd`'s PDA
  defaults, account roles and data. It also checks the Borsh `OracleCache` layout and the
  account discriminators, and `sync_lender`'s either-signer `owner` (`READONLY` as an address,
  `READONLY_SIGNER` as a signer; the lender PDA defaults from it).
